# Future With You V0.5.0 — 双人云端版架构

状态：开发中（`dev`）  
基线：V0.4.0 / 本地状态版本 3  
目标：让两个人在多设备上安全共享同一份故事，同时保留无网可用和完整导出能力。

## 1. 先澄清部署关系

Vercel 与 CloudBase 静态托管都只负责发布 React PWA。真正的数据边界由构建时选择的账号/数据库供应商决定。

```text
同一份 React PWA
├── Vercel Preview / Production
└── CloudBase 测试 / 正式静态托管
                 │
                 ▼
构建时只加载一个 Provider
├── Supabase      海外已验证基线
└── CloudBase PG  中国大陆 Alpha 3 候选
                 │
                 ▼
同一情侣空间的唯一数据真相
```

一个情侣空间只能选择一个权威后端。若两个人分别写 Supabase 和 CloudBase，他们看到的将是两个空间而不是“同步”；因此本项目不做跨云双写。大陆方案验收后，Vercel 与 CloudBase 两份前端也应指向同一个 CloudBase PG 环境。

## 2. 后端选择

Alpha 3 保留并隔离两条能力：

- Supabase：已经通过海外注册、登录、CAPTCHA、资料和情侣绑定验收，是当前回滚基线。
- CloudBase PG：复用相同前端协议，实现邮箱 OTP、会话保持、内置风险图片验证码、资料和情侣绑定，供中国大陆链路验收。
- `dev` 只发布测试目标；`main` 只在 PR 评审和人工批准后进入正式目标。
- 两种浏览器客户端都只接受 Publishable Key；Secret Key、管理员密钥和服务端密钥永不进入浏览器、Git 或 `VITE_*` 变量。

Alpha 3 不上传愿望、回忆与照片。账号链路、数据权限、域名连通性和双设备绑定通过后，再进入无损迁移与核心同步阶段。

每个供应商的测试环境与正式环境必须由迁移文件保持同一 schema；Preview / `dev` 测试账号不得污染正式情侣数据。

## 3. 产品入口不强迫登录

礼物第一次打开仍然可以直接进入本地模式。登录是“开启双人同步”的升级动作：

```text
打开礼物
  ├── 暂不登录 → 延续 V0.4 本地体验
  └── 开启双人同步
        ├── 注册 / 登录
        ├── 创建情侣空间 或 输入邀请码
        ├── 预览 V0.4 本地数据
        ├── 双方身份映射
        └── 无损迁移并校验
```

这样不会因为账号系统尚未完成或网络不稳定，破坏现在已经可用的礼物体验。

## 4. 一个数据真相，两层持久化

- 云端 PostgreSQL：已绑定情侣空间的权威共享数据。
- IndexedDB：当前设备的工作副本、待上传操作、同步游标和图片上传任务。
- `localStorage` V0.4 状态：迁移前的只读来源和迁移后的安全快照，不会立即删除。
- JSON 导出：永久保留，云端版仍允许两个人把全部数据与媒体清单带走。

`dist/` 只存应用代码，不存用户数据。重新构建或发布不会删除数据库、对象存储或设备缓存。

## 5. 统一领域模型

所有共享实体都带 `couple_id`，并使用客户端稳定 ID，保证离线创建后可以幂等上传。

| 实体 | 关键归属 | 说明 |
| --- | --- | --- |
| `profiles` | `user_id` | 个人昵称、头像；本人可改，伴侣可读 |
| `couples` | `id` | 情侣空间本身 |
| `couple_members` | `couple_id + user_id` | 当前只允许一个用户加入一个活跃情侣空间 |
| `wishes` | `couple_id` | 内置或自定义愿望及收藏/完成状态 |
| `memories` | `couple_id` | 故事正文，可关联愿望 |
| `memory_media` | `couple_id + memory_id` | 只保存对象路径和元数据，不保存 Data URL |
| `daily_answers` | `couple_id + user_id` | 每个人拥有自己的答案，避免互相覆盖 |
| `anniversaries` | `couple_id` | 纪念日和重复规则 |
| `time_capsules` | `couple_id` | 创建者、开启时间、打开状态 |
| `notifications` | `couple_id + recipient_user_id` | 基础通知中心和已读状态 |
| `sync_events` | `couple_id + sequence` | 全局递增的增量同步日志 |

每个可编辑共享实体还必须有：

- `revision`：乐观并发版本号。
- `created_at / updated_at`：服务器时间。
- `created_by / updated_by`：操作用户。
- `deleted_at`：软删除墓碑，避免离线旧设备把已删除内容“复活”。

## 6. 情侣绑定安全规则

- 邀请码只能通过服务端 RPC 创建和兑换。
- 邀请码保存哈希，短时有效、一次使用，生成新邀请码会废弃旧邀请码。
- 客户端不能直接给自己写 `couple_id` 或插入成员关系。
- 解绑使用软退出；数据默认不立即硬删除。
- 解绑前 UI 必须先提示下载完整备份。
- 重新绑定前必须明确旧空间是保留、归档还是导入新空间，不能静默混合。

## 7. 离线同步协议

本地写入顺序：

1. 先更新 IndexedDB 工作副本，让 UI 立即响应。
2. 生成唯一 `operation_id`，写入 outbox。
3. 有网时按顺序批量推送。
4. 服务端按 `operation_id` 幂等处理，并检查 `base_revision`。
5. 拉取 `sequence > local_cursor` 的事件。
6. 应用成功后才推进本地游标。

Realtime 只是“有新事件了”的唤醒信号，不是数据源。WebSocket 丢消息、手机休眠或断网恢复后，客户端始终按游标再次增量拉取。

### 冲突策略

| 场景 | 策略 |
| --- | --- |
| 两人新增不同回忆 / 照片 | 追加合并 |
| 两人回答每日问题 | 按 `user_id` 分行，不产生覆盖 |
| 收藏、完成、取消完成 | 版本不一致时拒绝静默覆盖，刷新后让用户重试 |
| 同时编辑同一段长故事 | 保留服务器版本和本地冲突副本，人工选择 |
| 删除与旧设备编辑冲突 | 删除墓碑优先，编辑保存为可恢复冲突副本 |
| 个人资料 | 仅本人可写，按服务器 revision 更新 |

## 8. V0.4 本地数据迁移

迁移必须可中断、可重试、可回滚：

1. 登录并完成情侣绑定。
2. 生成迁移清单、数据摘要和 SHA-256 指纹。
3. 让当前用户确认自己对应 V0.4 的“我”，另一账号对应“她”。
4. 先上传图片，获得对象路径；失败时不改本地记录。
5. 按稳定 ID 幂等写入愿望、回忆、每日答案、纪念日和时间胶囊。
6. 从云端重新读取并核对数量、指纹和媒体状态。
7. 标记迁移成功，但继续保留 V0.4 本地快照和导出文件。
8. 只有用户主动操作时才清理旧 Data URL。

任何一步失败，下次都使用同一个 `migration_id` 续传，不会重复生成回忆或照片。

## 9. 图片链路

- 设备端先压缩并校验 MIME、尺寸和大小。
- 离线时 Blob 暂存 IndexedDB，不塞回 `localStorage`。
- 云端路径使用 `couple_id/memory_id/media_id.ext`。
- Bucket 默认私有；只有当前情侣空间的活跃成员可读写。
- 数据库只保存路径、MIME、字节数、宽高和排序。
- 删除回忆先写数据库墓碑，对象延迟回收，给误删恢复留窗口。

## 10. V0.5 分段交付

### Alpha 1 — 供应商无关基础

- 后端配置与供应商边界。
- 账号、情侣空间、同步、媒体协议。
- IndexedDB outbox 与同步游标。
- V0.4 迁移清单和安全提示。
- 供应商无关 schema；CloudBase PG 草案保留为延期参考。

### Alpha 2 — 账号与情侣空间

- 新建 Supabase 开发项目并配置 Vercel Preview 环境变量。
- 注册、登录、会话保持、资料页。
- 创建空间、邀请码、加入、退出。
- Preview 登录回调、网络诊断和环境隔离验证。

### Alpha 3 — 中国大陆账号与情侣空间

- CloudBase Web SDK v3、邮箱 OTP、会话保持和内置风险图片验证码。
- CloudBase PG 资料、情侣空间、一次性邀请码及 SECURITY DEFINER RPC 加固。
- CloudBase `dev` 测试部署、`main` 正式门禁与双设备验收手册。
- Supabase 海外基线保持可回滚；两个后端不跨云双写。

### Alpha 4 — 无损迁移与核心同步

- 迁移预览、身份映射、断点续传和云端校验。
- Wish / Memory / Daily Answer / Anniversary / Capsule 双设备同步。
- 登录前后和退出后的数据隔离。

### Beta — 图片、通知和离线

- 私有对象存储、多图片上传、失败重试和多设备查看。
- `sync_events` 增量拉取、实时唤醒、通知中心和已读状态。
- 飞行模式编辑、重连自动同步、冲突副本 UI。

### Release Candidate — 数据安全验收

- 双手机、双网络、切后台、断网、重复点击和时钟错误回归。
- RLS 越权测试、邀请码重放测试、媒体路径越权测试。
- 云端完整导出、恢复演练、解绑与重新绑定演练。
- Vercel Preview 与 Production 使用受控环境变量，并完成从 Preview 到正式环境的迁移演练。

## 11. 发布门槛

V0.5.0 只有在以下条件全部通过后才能合并 `main`：

- 任一设备离线写入后，恢复网络不会丢数据或生成重复实体。
- A 账号不能读取或修改其他情侣空间的数据和图片。
- V0.4 原始数据在迁移失败、刷新和重新登录后仍可恢复。
- 两台设备通过已选权威后端的正式域名看到相同云端数据；Vercel 与 CloudBase 前端不得分裂空间。
- 完整导出包含数据文件、媒体清单、schema 版本和校验摘要。
- API Key / service role 等管理员密钥从未进入浏览器包或 Git。
